# 深度优化报告——0.14.12 增量启发式场（2026-11-16e）

> 定位：剖析显示搜索本体（astar 36% + fillDistanceMap 24%）仍是主体。0.14.9 曾将
> "按 goalSet 缓存场"证伪（命中率 1.3%）——那是对**整场缓存**的证伪；本轮对组合
> 一致场（0.14.10）的结构重新审视后发现：**目标集只增时场可精确增量更新**。

## 1. 机制

组合一致场 = 组合图多源**精确**距离（0.14.10 的可采纳+一致证明）。Prim 布线
`astar(net, src, tree, hard)` 的 goal=生长树——commitPath 只增不减：

- 目标集只增 ⇒ 新场 = min(旧场, 新源 BFS)（路径终点的归属分解）
- 旧场本身满足 Bellman 方程（精确距离场）→ label-correcting FIFO 只松弛"能改善"
  的格（`hMap[t]>d` 严格下降才入队）→ 收敛终值 = 全源精确距离 = **与全量重算逐位
  一致**（同一数学对象）
- 更新成本 ∝ 改善区域（新路径邻域）而非全场 TS——Prim 多引脚网的逐边更新大幅变轻
- **失效面**：RMST 逐边换 goal（目标集替换）→ 已收录成员检测（任一 stamped 格不在
  当前集合）+ 数量检测 → 全量重建；掩码重建（passMaskEpoch 变，含 ripNet/restore/
  adoptShared 全部失效点）→ 场重建。重建松弛集与更新的松弛集逐字段同源
  （8 平面邻 mask 门控 + diag 门控 + 2 换层双端门控）
- **盲口径不适用**：分离场非精确度量（两层传播近似），增量更新不保其值——逃生门
  路径保持 0.14.8 原码逐位不变
- 更新队列用可增长 JS 数组（label-correcting 允许重复入队，定长 typed 队列有溢出
  风险）——正确性优先于微 perf

## 2. 验证

- **增量场 ≡ 全量场探针**：40 随机板全程协商，**146 次增量更新**后用全量
  fillDistanceMap 重算逐格比对，**0 失配**（违规即抛）
- **行为差分**：400 组随机板×配置（默认路径）vs 冻结 0.14.11 全流程逐态对拍
  **0 失败**（搜索行为逐位不变 → search-regression 金标准免重录）
- 真实板 A/B（交替序 3 轮中位数 + 结果 SHA-256）见 CHANGELOG 0.14.12 表
- 全量 npm test exit 0 + 浏览器四组全过（按惯例截图恢复）

## 3. 边界

- 收益集中在 Prim 多边网（FPGA 类多引脚）；2 引脚网每次 routeNet 仍付一次全量
  O(TS)（无增量机会）
- RMST 回退路径目标集逐边替换，不享受增量（检测后全量重建）——Prim 为主路径，
  RMST 仅 Prim 未全连时回退
- 改善区域大小依赖板拓扑；无逐板保证，实测见 A/B
