## 三、已验证教训（先实验验证再记录）

### L1 细间距 = 线宽/间距/过孔三参数联动（★最重要）

- **实验**（n44 SSOP-24 0.65mm，grid 0.325，其余参数固定）：

  | trackW | clearance | via | 连通 | DRC |
  |---|---|---|---|---|
  | 0.4 | 0.2 | 0.8/0.4 | 15/41 | 12 |
  | 0.25 | 0.2 | 0.8/0.4 | 26/41 | 8 |
  | 0.2 | 0.2 | 0.8/0.4 | 29/41 | 8 |
  | **0.2** | **0.1** | **0.6/0.3** | **41/41** | **0** |

- **根因**：焊盘影响区半径 `halfClr = clearance + maxTrackW/2`。0.65mm 间距、焊盘宽 0.4 时，格心到相邻焊盘矩形距离最小仅 ~0.125mm；halfClr ≥ 0.3 就把相邻焊盘之间的格全标记为影响区（重叠区属主 = -1，全网禁行）→ 引脚被邻居"封死"。
- **诊断特征**：`overuse=0` 却大量未连通——是**被堵死**，不是拥塞。看到这个组合先查线宽/间距，不要加迭代。
- **规则表**（本工具 + 嘉立创工艺映射）：

  | 引脚间距 | grid | trackW | clearance | via 外径/钻孔 |
  |---|---|---|---|---|
  | ≥1.27 SOIC | 0.6 | 0.4 | 0.2 | 0.8/0.4 |
  | 0.8 TQFP | 0.25 | 0.2 | 0.1 | 0.6/0.3 |
  | 0.65 SSOP | 0.325 | 0.2 | 0.1 | 0.6/0.3 |
  | 0.5 QFN/LQFP | 0.25 | 0.15 | 0.1 | 0.5/0.25 |

- 注意 `maxTrackW` 取全板最大（含 nets[].w 电源加宽）——细间距板上不要给任何网设宽走线。

### L2 协商迭代越多可能越差 → 已修复（历史最优保留）

- **实测**（n42 修复前）：maxIter 50 → over=99；maxIter 150 → over=240、连通 65→62。**更多迭代更差**。
- **根因**：协商器全网重布 + 历史代价单调增长 + **不保留历史最优**——`buildResult` 返回最后一轮现场，扰动会把结果搅得更差。
- **修复**（engine.mjs）：迭代边界按 routeScore 同序指标（失败×1e8 > 几何违规×1e4 > overuse）跟踪最优快照；finish 时若当前更差则回滚；几何修正循环入口清空最优（修正本意是离开当前状态）。
- **修复后**：n42 maxIter 150 → 65/65、DRC 0。maxIter 从此可放心调大。
- **泛化**：任何"迭代改进"类算法（退火/协商/优化器）必须带 best-so-far 保留，否则迭代预算不可调、结果随预算抖动。

### L3 spec 自检门：残缺 spec 会"假绿"

- **事故**：spec 生成器 `mk('DIP-N', 16)` 因箭头函数只透传一个参数退化为 2 脚——DIP 全被截短。45 脚的板变 31 脚**仍然 100% 通过**（布线器只对实际存在的焊盘负责）。
- **修复**：mk 透传 count；建立 spec 自检（坏引用/单脚网/焊盘重叠/脚数核对）作为跑测试前置门。
- **泛化**：批量测试的 spec 必须先过网表完整性自检；"100% 布通"不等于"电路完整"。

### L4 手动 QFP 封装四角重叠

- 四边等跨 qfpPads 让相邻两边的角焊盘同坐标（pin1 与 pin44 重叠）→ 工具 DRC 正确抓到（30 个焊盘重叠）。
- **修正**：垂直中线外移 `s + 1.1mm`，四角相邻边焊盘矩形间隙 = clearance。
- **泛化**：手动封装必须过"同元件焊盘两两矩形距离 ≥ clearance"自检；DRC 抓生成器 bug 正是工具价值。

### L5 单脚网 = 必然未连通

- n45 的 rx/tx/pc1/pc3/pc4/pc7 无第二端 → 永远差 1 焊盘，布通率上限被锁死。
- **泛化**：spec 生成后先跑 `erc`（工具已有该命令），单脚网/坏引用在布线前清零。

### L6 布局贴边饿死逃逸走廊 → 已修复（归因修正：起效成分是初始货架边距）

- **实测**（n39）：15 个 DRC 全部位于板边 y≤2.7——退火把 DIP-18 贴到板边（初始货架 margin 仅 0.5mm），顶排引脚逃逸走廊只剩 0.65mm，9 根并行线饿死。布局器只罚"出板"不罚"贴边"，无梯度可爬。
- **修复**：退火 cost 增加"焊盘边缘距板边 <1.2mm 每毫米罚 20000"线性梯度 + 货架初始边距 0.5→1.5。不封死贴边（连接器类 spec 仍可指定）。
- **修复后效果**：n45 从 2422s/54 错 → **119s/0 错**；n48 从 97%/42 错 → 100%/0；n36 3 错 → 0；n43/n44/n46 过孔数减半。
- **归因修正（后续 A/B 实验）**：同构建下 ew=0 与 ew=20000 在 n45、n51 上结果**完全相同**——起效成分是同批落地的**货架初始边距 0.5→1.5**，梯度罚本身在两块板上均未激活（惰性）。梯度罚保留作防护（opts.edgeWeight 可覆盖），密度自适应曲线经 A/B 证伪已回退。
- **泛化**：布局优化器只有"合法性"罚不够，初始布局就要为可布线性留边；一次提交多个改动时必须逐项 A/B 归因，否则会把功劳记错。

### L7 DRC 与合法性检查的容差要一致 → 已修复

- **实测**（n47）：过孔与焊盘矩形距离恰 = clearance（0.15=0.5-1e-16 级别），viaLegal 放行、DRC `d < viaOuter/2+clearance`（**无 -1e-9 容差**）误报。
- **修复**：该判距补 -1e-9。修复后 n47 → 23/23 DRC 0。
- **泛化**：同一边界判断在 viaLegal/DRC/布线器三处必须用同一容差口径；"恰好接触"（=）永远不算违规（H1 教训家族第三次出现：罚金、DRC、判距各一次）。

### L8 难度的真相：面积×扇出，不是脚数

- n49（100×70 大板、86 pads、27 网）229s 全绿；n52（LQFP100+TSOP44、166 pads、40 网、16 位总线）100% 布通。
- 反而 n45（45×30、97 pads、31 网 + 6 排针）曾不收敛、n51（32×24 小板）102 错。
- **总线类有天然并行通道；排针扇出与小板中心拥挤才制造死区**。脚数/板面积都不能预测难度；"IC 四周 2mm 内的元件密度"才能。

### L9 "贴边罚伤小板"被证伪——n51 残留的真因是布局-布线轮数

- 初判（已被修正）：n51 修复前 96%/34 错 → 修复后 100%/102 错+75 拥塞，疑似"贴边罚把元件推离边后小板中心更挤"。
- **A/B 证伪**：同构建同种子下 ew=0 / 20000 / 密度自适应三档在 n51 上**逐位相同**（84/84, via 39, over 75, drc 102）——贴边罚根本没影响它（n51 的 spec 元件本来就不贴边，罚金未激活）。
- **真因**：n51 卡在 rounds=2；`retry3` 用 rounds=3（布局-布线反馈循环多一轮热点反馈）→ 102 错 → 23 错。
- **AI 操作规程**：密板残留拥塞先试 rounds=3（反馈循环），再查器件间距，最后才考虑参数。
- 密度自适应权重：A/B 无收益，已回退为固定 20000。

### L10 布局-布线循环的停滞自适应重启 → 已修复（历经三版才做对，官方跑动 n40 100%、n42 清零）

- **实测**（n40）：恒 34/35（1 焊盘被围死）。实验发现 `placeAndRoute` 调 `autoPlace` **没转发 seed**——warmStart 第二轮沿用同种子 42，退火反复落回同一盆地。
- **三版迭代**（每版都被下一轮实验修正）：
  1. 每轮 seed+round（纯多样化）：n40 ✓ 35/35，但 **n49 翻盘轮被破坏**（r2 同种子延续是它的救援路径）→ 回退
  2. 固定前两轮延续 + 第 3 轮多样化：n49 ✓，但 **n51 的救援恰是 r3 同种子延续**（23 错 → 34 错）→ 回退
  3. **停滞自适应（最终版）**：默认同种子 warmStart 延续；相邻轮"布通/失败/DRC/拥塞"四元组无改进时，下一轮**还原 spec 坐标全新起始 + 换种子**。三案例全部满足：n40 r4 逃逸 35/35、n49 r2 翻盘 78/78、n51 r3 延续 23 错
- **两个隐藏坑（都是实验抓出来的）**：
  - 停滞判定用全 score 向量会被"化妆性改进"骗过（连通相同但过孔少 1 个 → 判为改进）→ 只比前 4 维
  - "全新起始"必须**还原 spec 坐标**——design 里留着前几轮的旋转/位置残留，重排起点不同，结果不可复现（33/35 vs 单独跑 35/35）
- **泛化**：多轮优化循环的重启策略必须区分"延续性价值"（warmStart 翻盘）与"多样性价值"（换随机源逃盆地），用停滞检测切换；且重启必须还原初始状态。

### L11 验证实验自身也要验证（seed 未转发事故）

- 实验 B 第一版：五个种子结果逐位相同 → 起疑 → 查调用链发现 seed 根本没传进 autoPlace。
- **泛化**：做 A/B 实验前先确认"实验变量真的进入了被测代码路径"；多组完全相同的结果本身就是红旗（合理的随机化不该逐位相同）。

## 四、本轮工具改进清单（含二轮"按经验优化"）

第一轮（第五轮测试期间）：

7. 密度自适应贴边罚：**A/B 证伪已回退**（n51 三档权重逐位相同；flat 20000 + opts.edgeWeight 覆盖保留）

## 五、遗留问题（4 项，均已定位）

1. n39：LED 排走廊 4 处走线-焊盘间距——10 条并行窄走廊的排布问题，参数无法救，需 spec 级拉开 LED/电阻行距
2. n40：100% 连通但 1 格结构拥塞（SW 阵列区，全新重启也复现）——grid 0.6 对该排布偏粗，可试 grid 0.5 或拉开 SW 间距
3. n51：小板密排 23 处——32×24 塞 94 pads 的物理密度边界，加大板幅即解
4. n52：总线逃逸 7 处——可通过 per-net 宽度或 viaCost 分层调优
