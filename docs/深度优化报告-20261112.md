## 3. 优化内容（全部保序——候选集是保守超集，findings/输出逐位不变）

### 3.1 checkDRC 四处全扫的标量快速过滤（本次主收益）
保序充分性的数学依据：焊盘边上任意点距中心 ≤ hypot(w,h)/2 ≤ maxPadR，故**违规对
的中心距 < 阈值 + 双半径**；逐轴分量同受此界——轴距超界者必不违规，直接跳过。
迭代结构（含 add() 顺序）完全不变。

- **pad×pad**：`|Δx|>R 或 |Δy|>R → continue`（R=clearance+2·maxPadR）；
  同时把 `Array.from({length:layers})` 从**每对一次**提升为全程一次
- **via×pad**：R=viaOuter/2+clearance+maxPadR
- **via×seg**：段 bbox 外扩 viaOuter/2+clearance+w/2，bbox 外者必不违规
- **seg×pad**：每段 bbox 外扩 half+clearance+maxPadR

### 3.2 netW 引用守卫缓存
`netW` 是 DRC/导出/buildModel markFixed 的热查找（原为线性 `find`）。WeakMap 按
design 缓存 **net 对象引用**（非 w 值）——w 现读，原地改 `nets[i].w` 立即生效；
nets 数组换代自动重建。语义与线性版严格一致。

### 3.3 computePour 边界边数组
轮廓跟踪的 `eFrom/eTo` 从 JS 数组 push 改为**两遍扫描 + Int32Array 预分配**
（首遍计数 EN ≤ 4·visCount）——削 GC 与装箱开销。

## 6. 未做留档（收益/风险比不足或破坏逐位一致）

1. **pour cell 分辨率放粗**（0.04→0.05mm 可省 ~36% pour 耗时）——改变输出几何，破坏
   逐位一致契约；如未来引入"快速模式"旗标可重启此项
2. morph 的 32 位字并行（word-parallel）行扫描——工程复杂度高，收益 ~2×
3. pour typed-array 缓冲池复用——GC 仅 2.2%，收益有限
4. computeRatsnest 手动走线走廊标记（0.7.0 引入）已按段 bbox 限域，无需再动

## 7. 第二轮（同日）：精确归因驱动的 pour/model 优化

第一轮收口后重新剖析并做了**分段计时插桩**（computePour 内部逐节计时），
把 26% 的 self time 拆到节：

| 节 | 优化前占比 | 根因 |
|---|---|---|
| 孤岛处理 | 40.6% | **负空间孤岛可达 152 万格**（大板面几乎全是），逐格 4 邻 BFS 逐格计数 |
| open 块（morph×4 + 回填 + 重洪泛） | 40.1% | 形态学每 pass O(NF)，热循环内 erode/dilate 分支 |
| 轮廓跟踪 | 8.7% | 边界收集/环构建 |

### 7.1 孤岛 always 快径（run-based 扫描线连通计数）
- always 模式（默认）负空间孤岛只需**计数与总面积**：run 行段 + 行间重叠合并
  （单遍 label 传播 + 小型并查集）与 4 连通 BFS 组件划分**严格一致**
- **两个位级一致陷阱（实测抓出并修复）**：
  ① 浮点求和顺序——"总格数×cell²"与 BFS"逐组件 a=n·cell² 累加"的浮点序列不同
  （9.939199999999998 ≠ 9.939200000000001）→ 改为按组件最小格索引（=BFS 行主序
  发现顺序）排序后逐组件累加，浮点序列位级相同；
  ② 并查集合并时计数/最小格未随 root 聚合（留在子 root 上的数会丢）→ 合并分支处
  同步聚合
- area/never 模式保留原 BFS（回填 vis 的语义不动）；always 的 done 排除语义由
  !vis 蕴含（孤岛格必 !vis），done 保持全零行为等价

### 7.2 routeBoard 候选会话共享 model
- createSession 每次调用 buildModel，而 routeBoard 的初始+候选×3+逐网优化共
  **5 次会话**——审计确认 model 在会话生命周期内只读（fixedOwner/padOwner/blocked
  等全部写点都在 buildModel 内，逐字段 grep 过）→ build 一次共享（opts.model 直通，
  line 5710 的 17.8% 先例同款手法）；并行变体走 worker 进程不受影响

### 7.3 morph erode/dilate 专用循环
分支提出热循环（拆成四个专用内层循环）。
