# 项目优化复查：交互性能与布线正确性

## 范围与方法

本轮修改对象是 `pcb-autorouter`（起点 `6259860`、0.14.3）。工作区旁的 Freerouting、study 和资料目录作为参考资料，不修改第三方源码。审查覆盖共享引擎、浏览器 UI/Worker、CLI、构建、预览服务器及相应测试；不是声称逐行阅读所有第三方库、历史案例和二进制资料。

先运行原有 `npm.cmd test`，全绿后针对未覆盖的边界构造反例，再实施局部修复。对原 HEAD 代码在内存中复现了混合线宽漏检、Worker 漏掉新增固定孔、CLI 布尔开关解析失败，避免仅靠修后测试“看起来通过”。不新增运行时依赖，不更改工程格式，不直接手改生成的 HTML。

## 改动

### 1. 网络面板避免反复计算长度下界

位置：[UI 网络面板](../src/ui.js)、[回归测试](../tests/ui-net-cache.test.mjs)。

原来每次 `renderNets()` 都对每个网络两次筛选全板焊盘并重新执行 `netLowerBound()`。选网、键盘选网、重命名和高速标记等不改变焊盘坐标的操作也重复执行。大扇出网络的 Prim 下界计算开销较大，可能阻塞主线程。

现在每次渲染只遍历一次焊盘进行分组，以每网有序 `[x,y]` 坐标列表为签名缓存下界。只有坐标或网络归属变化的网络需要重算。缓存仅保留当前网络集合，设计对象替换（导入、撤销/重做）时清空。保存的仍是真实焊盘数据，不改变计算公式或显示结果。

测试覆盖真实 `renderNets` 及其点击/键盘/高速标记回调，断言重复渲染不再调用下界求解，移动、增删、改网和设计替换会失效。性能复现入口：`node tests/bench-net-panel.mjs`，比较旧路径和缓存热路径，并校验结果相同；它只测面板几何准备，不代表整页、首次加载或布线速度。

### 2. 修复变线宽几何扫描漏检

位置：[引擎](../src/engine.mjs) 的 `auditGeometry` 与形状补线的共享违规归属扫描；[回归测试](../tests/mixed-width-audit.test.mjs)。

扫描按段左边界排序，却用当前候选段的半宽确定 `break`。后方段可能更宽，不能据前一个窄段的间距界提前终止。

最小反例：线宽分别 0.2 / 0.2 / 2 mm，间距 0.2 mm；A 竖段 `(5,5)→(5,6)`，B 竖段 `(5.5,10)→(5.5,11)`，C 竖段 `(6,5)→(6,6)`。旧审计返回无违规，但 A-C 距离仅 1 mm，小于所需 1.3 mm。

改为本层最大半宽确定安全终止界，再按当前段对真实半宽过滤；保留原排序和输出次序。测试包括最小反例、手动铜/反向端点，以及 80 个固定种子多层混合线宽板与独立穷举几何 oracle 的逐项对比。该修复可能使旧结果显示出原先漏掉的违规，不能宣称所有设计布线逐字节不变。

### 3. 单网重布不得使用过期模型

位置：[Worker](../src/route-worker.js)、[实际 handler + 引擎测试](../tests/worker-session.test.mjs)。

旧会话指纹遗漏 `stitching`、全局线宽、间距、过孔尺寸及部分网络规则。新增固定地孔后直接单网重布，旧障碍模型不会看到它；实测旧 handler 返回结果而不是 `stale`。

改为完整规范化设计的序列化快照：任何设计变化保守地要求重新建模，后续新增约束也无需维护字段白名单。代价是仅改元数据也可能要求整体重布，优先保证正确性。测试覆盖 25 类字段变更、不变设计重复重布、新孔穿铜的真实 DRC 冲突和整体重布避障。

### 4. CLI 策略契约

位置：[参数解析](../src/cli-args.mjs)、[命令分发](../ai/pcb.mjs)、[可靠性测试](../tests/reliability.test.mjs)。

- 将 `--no-joint-reroute` 正确声明为布尔开关，避免吞掉位置参数或报缺值。
- 在读设计文件/开始路由前验证 `--fanout-first` 枚举，保留 `off/auto/inner/outer/inner_first/outer_first` 兼容值。
- 将 `blindVias`、`compactPairs`、`jointReroute` 和 `fanoutFirst` 策略传入 `autopcb` 循环，避免这些已接受参数被静默忽略。
- 清除重复的 `--pair` 表项，保留 tune/diffz 支持。

最终 `npm.cmd test` 退出码为 0：核心 80 项、Node 测试集合 253 项、书籍知识 48 项、CLI 17 项、KiCad 插件 mock、模糊输入 39 项、交付物深度校验 7 项及优化验证 22 项全部通过。单文件源构建一致性、经典脚本解析守卫和 `git diff --check` 均通过。浏览器测试生成的截图已恢复原版，避免混入非必要二进制改动。

面板微基准实测（本机 Node v24.21.0，101 网络 / 1000 焊盘，其中一个网络含 600 焊盘）：

| 测量项 | 中位耗时 |
|---|---:|
| 原路径，每次重新分组并求下界（5 次） | 373.22 ms |
| 新路径，设计不变的缓存热路径（21 次） | 0.835 ms |

此样本的几何准备阶段约 447 倍提速，输出经逐项校验相同，坐标改变后也重新校验。不是完整页面或布线引擎的加速倍数；首次计算仍需付出下界求解成本，机器负载也会影响测量。

浏览器回归 `npm.cmd run test:browser` 全部通过：基础 16 项、工作台 16 项、画布视觉/几何 22 项，共 54 项，覆盖 HTTP 和直接打开 HTML、后台布线、单网重布、取消、导入、尺寸响应及四层显示。

Windows PowerShell 的执行策略会阻止 `npm.ps1`，本轮使用 `npm.cmd`，未修改系统执行策略。浏览器回归使用工作区已有 Playwright/Chromium，未安装依赖、未启动替代开发服务器。

## 后续建议（本轮未实施）

- 引擎目前集中在约 9,450 行单文件，CLI 与 UI 也偏大。建议后续按几何、模型、搜索、DRC、导出拆分，在保持单文件构建的前提下逐步迁移；不要与正确性修复一次性混做。
- `autopcb` 仍接受若干并行参数，但其 `placeAndRoute` 是串行布局-布线循环。应单独定义并行语义或拒绝未支持参数，不能仅透传就宣称实现并行。
- 形状补线取消后的 UI 会话标记与被终止 Worker 的状态同步值得另补浏览器回归；本轮未扩大取消状态机修改范围。（后续状态：已在[深度优化轮](deep-optimization-20261115.md)统一修复并补充回归。）
- `allNetGeoVio` 的过孔-过孔计数与逐网参考函数并非数值等价；当前调用主要消费零/非零，未确认实际行为差异，因此不将其包装为已修复的布线错误。
- 缓存只减少重复计算，首次载入超大网络、整列表 DOM 重建及首次下界求解仍有开销，可根据真实工程性能剖析再优化。
