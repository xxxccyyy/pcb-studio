# 案例 02：开源广场接力（立创开源硬件平台 · STM32 最小系统）

> roadmap #8 的外部实测。目标：验证 EasyEDA 导入→接力布线→交付全链对**真实开源
> 工程**的兼容性——iCEBreaker 案例（案例 01）证明外部真实数据是抓缺口最高效的方式。
> 获取路径：oshwhub 项目页 RSC payload 提取 projectid → `lceda.cn/api/projects/{uuid}`
> → documents 里 docType=3 → `lceda.cn/api/documents/{docUuid}` 的 dataStr（972KB）。
> 端点探测过程见本文末尾。

## 工程信息

- 项目：[STM32最小系统](https://oshwhub.com/shaowp/STM32zui-xiao-ji-tong)（shaowp）
- 文件：`projects/ext-oshwhub-01/PCB.json`（真实 docType 3，599 shape，editorVersion 6.5.22）
- 形态：**4 层板**（1/2/21/22 有铜）+ 边框层 10 + **80 个 LIB 封装（全部无 `name`
  属性、全部 doc 绝对坐标）** + 异形铜皮 SOLIDREGION + DIMENSION/SVGNODE 装饰

## 命令日志（0.11.2 修复后）


## 布通率分析（头部遗留项）

| 场景 | 连通 | 说明 |
|---|---|---|
| 导入 manual=158（接力原样） | **53/203** | 全部来自导入走线自身（每 manual 网 1/1），自动布线 0 新增 |
| manual=79 | 86/203 | |
| manual=10 | 103/203 | |
| manual=0（纯网表） | **104/203** | 自动布线器上限 |

**每条 manual 走线约挤掉 0.3 个连接**——线性侵蚀。根因不是 bug：markFixed 的
manual 影响区（netW/2+clearance+maxTrackW/2 ≈0.77mm 禁行带）×158 条 ≈ 49% 板面
对其它网封闭，剩余走廊在栅格模型下不可达。这**正是路线图阶段三 #12（形状布线
expansion rooms）的目标场景**——高占用板的接力补线。降过孔代价（vc5）无改善，
佐证不是换层代价问题而是区域封闭问题。

**接力场景的实用建议**（写入 AI 手册的口径）：对已布高占用板，本工具的定位是
「查看/标注/DRC/导出」而非全量补线；补线建议按网手动（route 单网能力已有）。

## 0.11.4 追加：位号回收 + 铺铜重铺验证

- **位号回收 80/80**：真实文件的 80 个封装 attrs 全无 `name`，但**每个 LIB 内部
  恰好有一个位号样式 TEXT**（所有权 1:1 明确）——导入器把无名 LIB 组的内部位号
  TEXT 回收为组名（同名冲突/缺失保 LIB{n}；顶层 PA12 类网名不参与防误配）。
  实测：**组件 80/80 全部找回真位号**（U15/U2/LCD2/USB1/R5/C15/LED1...，零残留
  LIB{n}）——BOM/贴片坐标分组恢复真实语义。回归：easyeda-import「无名 LIB 位号
  回收」测试（回收/冲突/缺失三分支）。
- **铺铜重铺验证**：`pour --net GND --layer bottom` 在真板上 ok、6 个缝合孔自动
  生成、unconnectedPads 空（GND 焊盘全接入）、**DRC 0 errors / 0 warnings /
  0 fabFail**——接力链的铺铜环节在真实 4 层板上全绿。

## 遗留清单

1. 布通率 51%（纯网表口径）——根因=栅格模型在高占用板的走廊破碎，#12 形状布线
   立项的实证依据（本案例即其验收用例）
2. 层 23 走线 5 条（**5/6 层板**的第 3 内层）超出 1/2/4 层模型——如实跳过计数；
   支持更多内层属模型扩展项
3. COPPERAREA×3 + 异形铜皮×1 未导入——`pour` 重铺流程待在此板验证（面积/间距
   对账）
4. DIMENSION×2 / SVGNODE×4 装饰跳过（合理，无需处理）
5. ~~位号全部降级 LIB{n}~~ **已解决（0.11.4）**：LIB 内部位号 TEXT 1:1 回收，80/80 找回真位号

## 端点探测记录（获取路径）

1. `oshwlab.com`（国际版）首页为 Next.js，无直连 JSON
2. 项目页 RSC payload 内含 `projectid`（32 位 hex）
3. **`https://lceda.cn/api/projects/{projectid}`** → 200 JSON（documents 数组含 docType）
4. `https://lceda.cn/api/documents/{docUuid}` → dataStr = docType 3 PCB JSON ✓
5. 注：oshwhub 与 oshwlab 同源；专业版工程（.epro2）不适用本链路（格式不同）
