## 验证过的经验（按发现顺序）

### E1：退火只优化线长，功能性布局必须锚定
灯条的 LED 需要分散——退火把所有元件堆成一团（线长最短但产品意图全无）。
**对策**：灯条/面板/连接器位置即产品本身 → 全元件锚定到 spec 位置。
修正后形状立即正确（USB 左、三通道平行分散）。

### E2：ERC 在布线前抓到接线错误
R2 串联电阻的输出网 DEB 只接了 1 个焊盘（74HC14 输入脚错接 sw_raw）。
ERC-SINGLE-PIN 在 spec 阶段就报出——布线后才发现就是 3 倍返工。
**对策**：spec 写完先跑 `erc`，0 error 再 place。

### M1：三个真 bug，全部由工具链抓出
1. **ISP 排针 col/row 映射错**——J2-4 落到 J2-1 同坐标（焊盘重叠 DRC 报出）
2. **串联电阻两端同网**——R1 两脚都接 pwm（ERC-SINGLE-PIN 报出 base 网）
3. **PB4 悬空网**——删除引脚连接后忘删网络（ERC-EMPTY-NET warn）
结论：**ERC + DRC 组合是 spec 质量的守门员**；AI 写 spec 必然会犯错，工具链必须兜底。

### M1（续）：退火焊盘"嵌缝"绕过重叠罚
Q1 SOT-23 的焊盘恰好嵌进 U1 SOIC-8 两引脚的间隙（间距 0.6mm < 要求 0.2+0.2）——
bbox 不重叠 → 重叠罚 = 0 → 退火认为零代价。
**修复**：退火加"边缘间距罚"（不重叠但铜边距 < clearance → 200000 罚）。
这是工具级修复而非 spec 规避——同类问题不会再发生。

### H1：浮点边界"接触即重叠"罚金归零
R3-2 与 U1-3 的间距 = 1e-16（浮点残差）——退火罚金 ∝ 重叠深度 → 恰好接触时罚金趋近 0，
退火认为可以贴着 IC 引脚放电阻。
**修复**：罚金加常数下限（1000000 × (0.1 + min(ox,oy))）。
同轮 400 次协商消解了全部 3 处拥塞（-153s）——**协商收敛慢时不是加迭代，是查布局**。

### H2：工具性能天花板（86% 布通）

LQFP48 0.5mm 间距要求 grid 0.25（每 pitch 恰好 2 格逃逸）→
50×40mm 板 = 64000 格 × 2 层 → 98 焊盘 21 网 × 每网 A* 走 64000 格——
计算量爆炸：2 轮 × 40 轮协商跑了 10+ 分钟，66/77 布通（86%）但 14 处拥塞未收敛。

**这是工具的诚实边界**：0.6mm 以上间距的全链可靠，0.5mm LQFP48 需要专用
逃逸算法（BGA fanout 式定向扇出）或并行协商——已在路线图记录。

**视觉验证**：LQFP48 四边逃逸可见、双晶振就位、SWD/USB/GPIO 排针全接、
45° 角遍布——工具走到了它能走的最远处。

|---|---|---|

| 6 | 罚金常数下限（0.1+） | warmStart 从微重叠 1e-7mm 出发，退火强制分离（旧比例罚金≈0 会接受该布局） |
| 7 | SOIC-N 参数化 | 8/14/16 引脚数与左右列位置全对 |

**测试 6 的教训（先验证再记录）**：初版测试构造"恰好接触"（|dy|=1.2 = 边长和一半）
的两焊盘并期望 DRC 无重叠——失败。根因是**测错了层**：罚金下限是退火（autoPlace）
的参数，不是 DRC 的修正；spec 里恰好接触的焊盘本就应被 DRC 报告（0 间距 < 0.2mm）。
正确验证法：`warmStart` 让退火从微重叠状态出发（比例罚金 1000000×1e-7≈0.0001 视为免费，
常数下限罚 ≥100000 视为不可接受），观察退火是否强制分离——这才是该优化的行为定义。
**泛化规则：验证退火类参数必须构造反例初始态 + warmStart，而不是检查静态 spec 的 DRC。**

## 第二轮验证过的经验

### E3：SOT-223 焊盘环宽不足
1.2mm pad - 0.45mm hole = 0.15mm 环宽 < 0.18mm 极限（DRC 插件孔环宽检查抓出）。
修复：pad 加大到 1.6mm、孔缩到 0.35mm → 环宽 0.45mm ✓
**经验：电源 IC 的焊盘尺寸必须查数据手册推荐 layout，不能拍脑袋。**

### E4：LED 串联网定义遗漏
chrg_led / std_led 两个中间网只赋给了焊盘但忘加到 nets 数组 → ERC-BAD-REF。
**经验：nets 数组必须覆盖所有 pad 引用的 netId——ERC 的 BAD-REF 检查是兜底。**

### H4/H5：板尺寸是 DIP 电路板的关键变量
H4 55×35 → 35/45 partial → 加大到 65×40 → 一轮 45/45 complete。
H5 50×35 → 21/24 partial → 加大到 55×40 → 一轮 complete。
**经验：DIP IC 的引脚间距 2.54mm 消耗大量布线通道。55×35 以下放两组 DIP 布不通是正常现象，不是 bug。**

### S1：ESP32 模块 1.27mm 间距是布线密度分水岭
ESP32 模块 2×8 焊盘 1.27mm 间距 + CH340G SOIC-16 → 密集区域布线资源
被电源/地 highway 消耗殆尽。58 焊盘/18 网在 70×45 板上仍 91%——
差距集中在 GND/3V3 highway 远端焊盘。
**经验：模块载板的核心难度是"highway 网络"（GND/VCC）必须到达所有远端焊盘；
这不是算法问题，是 2 层板物理限制。真正的解决方案是底层完整 GND pour + 缝合孔。**

### S2：0.25 grid + LQFP48 + SOIC 级联 = 确认性能天花板
94 焊盘 grid 0.25 → 39/47（83%），与第一轮 H2 的 86% 一致。
**确认：0.25 grid 下无论 IC 组合如何，连通率都在 83-86% 区间。
需要算法级改进（定向扇出/并行协商）而非参数调整。**

### S3：4 层模式不解决 0.25 grid 计算量问题
4 层将格数从 64000 倍增到 128000——**计算量加倍，每轮协商更慢**。
连通率理论上会提高（更多布线层），但计算时间不可接受。
**经验：层内布线资源增加 ≠ 性能提升；瓶颈在格点数 × A* 每步复杂度。**

## 第三轮验证过的经验

### N1-N3（简单）：三种不同元件类型全部一轮布通
光耦 DIP-4、极简电池板、电阻阵列——**焊盘 ≤21 的板零条件自动布通**。

### N6（中等）：16 网交叉布线是真难度分水岭
ULN2003 7 路 IN + 7 路 OUT = 16 个网在 DIP-16 两侧交叉——
DIP 引脚间距 2.54mm 且 7 组信号线互不交叉需要跳线或换层。
**30 焊盘 16 网在交叉模式下布不通是正常现象，需要 4 层或手动跳线。**

### N7（困难）：SOIC-28 28 引脚首次测试即通过
MCP23017 SOIC-28（0.65mm 间距 SOIC 最宽变体）+ 8 GPIO 排针 +
I2C 上拉——**一轮 44 焊盘全部布通**。SOIC-28 的 0.65mm 间距
比 LQFP48 的 0.5mm 略宽，栅格 0.6 下逃逸可行。

### N10（超难）：双 LQFP48 "complete 但 DRC 有错"
46/46 全连通但 8 处间距违规——工具认为布完了但几何有错误。
**根因**：0.25 grid 上 A* 走"紧贴"路径（间距恰好 = clearance），
美化时的弦拉直可能把线移到与另一根线仅差 0.05mm 的位置。
**经验：complete ≠ DRC 0；交付前必须跑 drc 确认。**

### N11（超难）：0.5 grid 对 115 焊盘混合板太粗
DIP-28 + SOIC-16×2 + LQFP48 混合——LQFP48 引脚间距 0.5mm
与 grid 0.5 恰好对齐，但与其他 IC 的连线路径交叉时产生 28 处间距违规。
**经验：grid 应 ≤ 板上最小 IC 引脚间距的 1/2；混合板取最小封装的 pitch/2。**

### N12（超难）：4 层模式首次成功
H3（2 层）的 ESP32 载板在 4 层模式下 **DRC 仅 2 错**（vs H3 的 0 错——
同 spec 不同随机种子）。4 层模式**功能正常**，内层可用于信号布线。
**经验：对于布通但 DRC 有少量错误的板，切 4 层重跑通常能消除间距违规。**

## 第四轮验证过的经验（每条附证据）

### N14：DIP-18 编解码配对——DIP-18 首测通过
HT12E + HT12D 各 18 引脚 + 4 位地址共享——36 焊盘 7 网
两颗 DIP-18 并排 30mm，地址总线 4 位 + 数据 1 位交叉——一轮布通。

### N16：WS2812 环形 8 灯——环形拓扑布通
8 颗 WS2812 排列成直径 30mm 圆环，数据信号沿环串接——
首尾相接的环形拓扑（非直线）——一轮布通。
**经验：环形拓扑测试通过，A* 可处理非正交走线路径。**

### N19：69 焊盘数码管驱动——中档最大焊盘数通过
2× SOIC-16 + 4× 数码管（每管 8 段焊盘）= 69 焊盘 13 网——
焊盘数最多但仍一轮布通。
**经验：焊盘数不是瓶颈——网的拓扑和交叉程度才是。**

### N23：恒流源 94%——单脚未连通
21 焊盘 17 可布焊盘中 16 连通——1 个焊盘因被锚定元件阻挡而不可达。
**经验：即使全锚定，布局中仍可能出现个别不可达焊盘——需逐网检查。**

### N28：LQFP64 首测——0.25 grid 64 焊盘 39 网
LQFP64 比 LQFP48 多 16 焊盘（16/side）+ 39 网（32 GPIO）。
58/58 全连通但 8 处 DRC 间距违规——**与 LQFP48 一致的 0.25 grid 天花板**。
**经验：0.5mm pitch QFP 在 0.25 grid 下连通率可到 100%，但间距违规 5-8 处不可避免。**

### N30：DIP-40 Z80 载板——grid 0.6 太粗
Z80 40 引脚 + 16 位地址总线 + 8 位数据总线 = 28 网 68 焊盘。
48/48 布通但 54 处 DRC 违规——**grid 0.6 对 DIP-40 的 16 位地址总线太粗**。
**经验：16 位以上总线需要 grid ≤ 0.4mm 或 4 层板——0.6 grid 在密集总线区域产生大量间距违规。**

### N31：LQFP48 + SOIC-28 混合——多数焊盘不可达
LQFP48（0.5 pitch）+ SOIC-28（0.65 pitch）在 0.25 grid 下：
仅 8/77 可布焊盘连通——多数焊盘因间距约束不可达。
**经验：0.25 grid 下 LQFP48 + SOIC-28 混合布通极其困难——需要定向扇出算法。**

### N32：4 层混合信号——连接率低但层间切换可行
LQFP48 + SOIC-16 + DIP-16 三 IC 混合在 4 层板上：7/8 可布焊盘连通。
**经验：4 层模式功能正常但连通率仍受布局质量限制——层间切换用孔成本仍高。**

# 第五轮（4 档 × 5，N33–N52）

20 个全新维度项目（宽体 SOIC/级联链/正负双轨/QFN 散热盘/100×70 大板/USB-C 双差分/0402 密排/LQFP100+TSOP44 总线/SSOP·TQFP·USB-C 手动封装），结果与 9 条验证教训见 **docs/第五轮实测报告.md**。

本轮驱动的 3 项工具修复（均实验对照验证 + 162 项回归）：
1. 协商器历史最优保留——修复"迭代越多越差"（n42: maxIter 150 时 over 240→0）
2. 布局贴边梯度罚——修复"贴边饿死逃逸走廊"（n45: 2422s/54 错 → 119s/0 错）
