# 引擎优化：拥塞代价正确性、过孔检查缓存与固定孔制造约束

## 目标与证据边界

本轮把“提高良率”拆成能验证的设计指标：未连通数、几何 DRC、钻孔边距、过孔数和线长；没有板厂生产统计，不把这些结果称为实际生产良率提升。

改动前引擎保存在本地 `.scratch/engine-quality-20261115/engine-before.mjs`。所有对比使用相同设计输入和参数，不改焊盘位置、线宽、净距或板层来获得更好数字。保留上一轮未提交改动和用户已有工程结果。

## 1. 修复协商搜索的邻域坐标错误

位置：[引擎 soft A* 邻近代价](../src/engine.mjs)。

旧代码将 `ns % NC` 当作列号、`floor(ns / NC)` 当作行号；实际这两个值分别是单层线性格号和层号。四邻拥塞与高速网 3W 环因此会漏算、跨行或跨层计算。

改为先求单层格号，再分解真实列/行。高速网的同网与差分伙伴豁免保持原定义。还修复了 TS>4M 时关闭 `nearPenCache` 后仍无条件写 null 缓冲的崩溃。

[独立坐标 oracle 回归](../tests/congestion-neighborhood.test.mjs) 逐层逐格覆盖边界、四邻/3W、同网/差分豁免、缓存命中和 null 回退。原引擎在普通内部格上与四邻 oracle 不一致，null 回退抛错，均在修前快照独立复现。

### 同输入 21 案例质量对比

[复现脚本](../tests/bench-engine-quality.mjs)：15 个共享搜索场景与 6 个 round11 工程，`maxIter=10`，双方均关闭 compactPairs/jointReroute 以隔离本轮搜索代价影响，其余 `routeBoard` 优化开启。每个版本独立复制设计运行，再检查实际几何 DRC；耗时只单次采样，不能作为稳定性能数据。

| 指标 | 改前 | 改后 |
|---|---:|---:|
| 未连通合计 | 0 | 0 |
| 几何 DRC error 合计 | 61 | 48 |
| 过孔数合计 | 90 | 115 |
| 线长合计 | 4906.51 mm | 4593.09 mm |
| 按现有 routeScore 比较 | — | 7 好 / 10 同 / 4 差 |

逐案例原始数据见 [21 案例完整测量](engine-quality-comparison-20261115.json)，包含制造检查计数与两个版本的评分。

**这不是全面无损的质量提升**：修正拥塞模型改变启发式搜索结果，某些板以更多过孔换取更短线长；当前评分把过孔数排在线长之前，所以如实记为退步。未连通和几何 DRC 在这些案例中没有变差，但不能据此承诺所有设计都不退步。

代表变化：p27-cnc-shield 几何 DRC 55→42，仍是 partial，不能交付生产；MCU 默认场景线长 327.63→309.36 mm 且保持零过孔/零 DRC。p19-star-7 7→19 孔、p45-center-keepout 13→24 孔，是必须保留的反向指标。

### 搜索黄金样本迁移

旧 [search-baseline.json](../tests/search-baseline.json) 保留不覆盖。修正代价模型后，15 个配置中 7 个完整阶段结果变化，新增 [修正邻域基线](../tests/search-neighborhood-baseline.json)，连续两次运行严格相等后记录；[搜索回归](../tests/search-regression.test.mjs) 改为守住该基线。

这不是“仍与历史分配版位级一致”，因此改名并记录原因；独立邻域 oracle 负责验证模型语义，而不是只更新哈希掩盖错误。

## 2. CPUprofile 驱动的过孔环代价缓存

真实 ext-fable-03 的 `createSession(maxIter=8)` CPUprofile 中，A* self 约 78%，过孔环的 usage/ownStamp 逐层扫描是显著热点。以往认为缓存必须区分换层层对，但该环的偏移排除了 `(0,0)`，环格不会等于换层中心，原 `rs===cur/ns` 过滤不改变任何环格。单次 A* 内 usage、ownStamp、hard 和 presFac 都固定，结果只依赖 `(cell,gen)`。

采用 Float64 罚分和 Int32 代际戳；存储保持原逐层求和结果，硬冲突以负哨兵记录。每次搜索换 gen，restore/单网重布/协商都不会沿用旧值。仅 NC<=1,000,000 时启用，新增内存上限 12 MB，超过预算直接原扫描；过孔合法性和层跨度门禁仍先执行。

[缓存回归](../tests/via-ring-cache.test.mjs) 覆盖同格不同层对、软/硬、代际/usage/presFac/属主变化、边缘、预算与无缓存回退、15 个示例配置、2/4 层盲孔、restore→optimize→reroute；对照是[当前引擎仅关闭本缓存](../tests/via-ring-reference.mjs)，避免与上面的正确性修复混淆。

[性能复现](../tests/bench-via-ring.mjs)：真实板交错开关缓存，首轮预热后 5 次中位数约 7100→6044 ms（-14.9%）。最终源码在全量测试完成后再次独立复测，5 次中位数 **6614.75→5695.06 ms（-13.9%）**，所有几何和统计严格相同；[最终原始样本](engine-cache-benchmark-20261115.json) 已保存。测量范围仅会话布线（maxIter=8），不含 routeBoard 多候选/后优化/美化，也不是整个应用加速比。

## 3. 自动过孔避开已有固定孔的钻孔风险

既有铜间距检查对同网放行，不代表可以在同网钻孔旁再钻一个过近的新孔。原来只对 THT 焊盘孔做硬门，没有覆盖已存在的缝合孔和手动换层孔。

12×12 mm 最小例中，上下两面同网 SMD 盘重叠于 `(5.25,5.25)`，同网固定孔在 `(5.75,5.25)`，viaDrill=0.4 mm。旧搜索直接在焊盘中心换层，物理孔边距仅 **0.10 mm**，DFM 报过孔间距 warning，但几何 DRC 仍为 0。

现在会话仅在有固定过孔时，按 `manufacturingHoles + manualRouteEntries` 相同口径建立按 X 排序的固定孔表；过孔候选通过二分与安全半径筛选，再按实际钻孔半径、JLC 孔边距和钻孔跨度检查。同网不豁免；仅已知同网、完全相同 XY、孔径和跨度的孔可复用；不相交埋孔跨度不误挡。

修后该例保持 100% 连通、自动过孔仍 1 个、零几何 DRC；新孔移动至 `(5.25,5.75)`，实际孔边距约 **0.307 mm**，DFM 过孔间距 warning **1→0**，线长代价约 +1 mm。

[7 项固定孔测试](../tests/fixed-via-drill.test.mjs) 覆盖真实 stitching/manual 路由、optimize 开关、精确边界、等价孔复用、异网/孔径/跨度和 1000 次索引与全扫对拍。也覆盖固定孔与 THT 合并后的记录：不能因记录同时带 pad 字段而丢掉固定钻孔，尤其需要保留未显式指定 holeR 时的制造孔径回退。

范围限制：本项保护的是新增自动孔对**已有固定孔**的间距；不声称已经解决同一次 A* 路径中新生成的两颗同网孔之间的所有钻孔风险。DFM 仍需完整运行，既有过近固定孔也不会被自动移动。

## 4. 全阶段回滚后的差分对报告

首次全量回归中，两项既有差分对测试失败：搜索代价改变后更容易触发整个后优化阶段回滚，`routeBoard` 恢复了几何，却没有把压实报告带回最终结果；会话中还可能留着描述被回滚尝试的旧报告。

修复仅报告状态，不放宽接受门禁：回滚时根据最终保留几何重算耦合占比，标记 `rolledBack:true`、`compacted:0`、`action:skipped` 和回滚原因，DRC 数取最终结果；后续会话 `buildResult` 同步同一报告。[原差分对测试](../tests/pair-compact.test.mjs) 保留原断言，并增加会话/结果报告一致性及不得误报压实成功的断言。35 项相关回归已通过。

## 5. 未落地的方案

- 尝试“低过孔代价救通后再追加高过孔代价重跑”：p19 19→12 孔、p45 24→16 孔，但额外耗时约 50%，仍不及旧启发式的孔数。本轮不默认增加该轮重跑，避免用更多尝试冒充算法提速。
- 大板板边标记由全场扫描改周长扫描，模型微基准有毫秒级收益，但小板反而变慢，不是当前主热点，未合入。
- 大规模模块拆分、真实生产良率统计、全局同网动态孔距状态扩展不在本轮完成范围。
