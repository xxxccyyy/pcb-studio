## 二、已验证教训（先实验验证再记录）

### L31 质量体系稳态：连续三轮零失败（R7/R8/R9）

- **事实**：R9 全部 20 项目**首轮通过**——自检门拦截全部 spec bug（含连续第五轮复发的 `netObjs` 键名错误、QFP 直接 add() 漏偏移等生成器惯用法错误），布线阶段 0 DRC 错 0 未连通，无需任何修复重跑。
- **对照**：R1-R5 每轮 4-10 个失败项目；R6 3 项引擎修复后 R7 零引擎 bug；R8 新几何家族引入 1 个引擎 bug（当轮修复）；R9 引入 14 种新封装/10 类新拓扑**零失败**。
- **解读**：修复以几何定理落地（而非补丁）后不复发；spec 门把失败类前移到布线前。**测试的压力承载从"引擎正确性"转移到"新维度覆盖"——这正是工具级布线器应有的稳态。**

### L32 启发式图缓存：A/B 证伪 → 回退（本轮深度优化的负结果）

- **剖析**（n130，CPU profile）：astar 45.9% + 堆 pop 14.1% + **fillDistanceMap 28.0%** = 88% 热点。fillDistanceMap 是目标集到全场的可采纳启发式 BFS（忽略障碍），每次 astar 调用全图重算（13.5 万格）。
- **假设**：该图只依赖 (目标集, viaCost, diag)，与布线状态无关 → 按目标集缓存可消除 28%。
- **实验**：实现 FIFO 缓存（viaCost/diag 变更清空，上限 24 图防内存膨胀）→ 输出逐位一致（complete 119/119 via=24）但 **858.0s vs 基线 875.6s——收益 2%，低于同配置机器噪声（6%）**。
- **插桩归因**：**命中率 1.3%**（60608 次调用仅 800 命中）。根因：astar 的 goalSet 是 **RMST 逐边目标集**，含动态布线格（斯坦纳点/已布 cells），每轮撕线重布后键变化 → 键空间近乎每次唯一。
- **处置**：**回退**（复杂度+13MB 内存换不来噪声级收益），代码留档注释。**泛化**：缓存设计前先验证"键的重复率"——剖析给的是函数级占比，不是可缓存性；插桩命中率是缓存的先行指标（本例 5 分钟插桩就避免了错误落地）。
- **性能 roadmap**（按剖析证据排序）：① A* 内环与堆（60%）：类型化数组堆替代 JS 数组堆、邻居生成的分支消除；② fillDistanceMap 微优化（闭包内联/Int32 距离/层扫描合并）；③ 算法级：双向 A* 或增量启发式——**均属行为级变更，须逐项 A/B（输出逐位一致才算通过）**。

### L33 新拓扑维度全过：链/环/塔/反馈结构无需特判

- **链式递进**（n126 倍压梯、n128 PMT 12 级分压塔、n122 峰值链）：Steiner 树 + 逐边布线对"相邻节点短链"拓扑天然适配，0 过孔。
- **逻辑闭环**（n117 环形振荡器、n119 PLL 反馈环、n131 文氏桥 AGC）：电路意义上的环在网表里全是普通 2-3 焊盘网——**布线器无环问题**（物理环 vs 逻辑环的区分，打消"反馈环布不通"的直觉担忧）。
- **大电流脉冲回路**（n132 频闪：储能电容堆+SCR+灯堆）：clearance 0.3 高压口径 + 大孔 THT 全过。
- **高压分压结构**（n125 盖革 400V、n128 PMT）：clearance 0.3 全局口径下高压链正常（>100V 间距为检查表人工项，与 R7 n86 一致）。

### L34 修正第八轮 roadmap 误判：半孔环宽无需"半环计算"

- **R8 原判断**：「DRC 环宽检查对 castellated 特征按半环计算」列为 roadmap。
- **复核**：环宽定义 = (盘径 − 孔径)/2，**对半孔同样成立**（半孔只是环被板边截断，径向宽度不变）。R8 n110 的 20 个环宽错误真因是孔径=盘径（1.0/1.0 → 环 0），spec 级放大盘径（1.1）即正确解决——DRC 无需任何改动。
- **修正**：撤下该 roadmap 项；DRC 契约在半孔上**没有**空档（出板豁免是唯一需要的特例，R8 已实现）。
- **泛化**：roadmap 项也要复核——"检查缺一个特例"与"参数选错"的表象相同，归因错了会把正确的检查当作缺口。
