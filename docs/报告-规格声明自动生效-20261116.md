# 报告：规格声明 → IPC/IEC 标准自动生效（0.14.6 批次1-3）

> 2026-11-16 · 每批次独立深检后提交；本文为收口汇总。

## 一、背景与模式

规格书/数据手册里有物理约束数据，但引擎声明入口此前只有全板统一默认值。
0.14.2-0.14.4 的"电流→线宽"是第一个实例。本轮按同一模式补齐：

**声明（nets[]/rules 字段）→ IPC/IEC 标准查表 → 内核自动生效 → DRC 校验 → 报告面**

三批全部完成，每批独立深检（查表数值独立校验 + 真板端到端 + 导出链路 +
全量回归 + 永久测试锁定）后独立提交。

## 二、批次明细与验证证据

### 批次1：电压→安全间距（IPC-2221B Table 6-1）

| 项 | 内容 |
|---|---|
| 声明 | `nets[].voltage=V`（如 170） |
| 标准 | `ipc2221Clr` 阶梯查表：B1 内层 / B2 外层涂层 / B4 外层无涂层（打样最严缺省）；15V→0.1、50V→0.64、150V→0.64、170V→1.27、300V→1.27、500V→2.5 |
| 生效 | 该网有效间距 `max(全局,标准)`（`netClr`）；buildModel 焊盘影响区 per-pad 化（高压焊盘推开异网更远；无声明网位级不变） |
| 校验 | 20a 锚点数学、20d 混合电压板端到端（布线 complete + DRC 0 + EasyEDA verify PASS + Gerber 8 刀 + IPC-356） |
| 提交 | a485135（实现）+ 7a0231a（20b 断言语义升级） |

**20b 深检发现**：netW 内核自动抬宽使检查表的"fail 触发"路径不再可达
（0.4mm 走 8A 在检查表读到 5.06mm 时已被内核抬宽）——检查表语义升级为
"最终宽度确认行"，fail 拦截职责归 spec 门（读到原始 spec 级数据）。测试
同步锁定原地改写行为（batp.w≈5.06）。

### 批次2：过孔载流 + 热过孔阵列

| 项 | 内容 |
|---|---|
| 过孔载流 | 0.3mm 孔保守 1A/孔（`JLC.viaAmp`）。检查表"换层过孔并联"行：实际 = 布线换层孔 + 同网 stitching，少于 `ceil(I/viaAmp)` warn；0 孔=同层走线 ok。布线器不自动加孔（几何约束复杂，报告给调用方——计划原文口径） |
| 热过孔阵列 | `thermalViaArray(design, compId, opts)`：元件面积最大焊盘（散热盘）下生成 0.3mm 阵，缺省按焊盘自适应（3×3 起，DPAK 舌片 6.5×7 → 6×7=42 孔）。几何约束逐孔校验：孔心收进 viaOuter/2（整孔盘含在焊盘铜内）、距焊盘自带插件孔 ≥ holeR+drill/2+viaEdgeMin（TO-220 舌片，DRC 同网不豁免口径先滤）、pitch ≥ viaOuter+viaEdgeMin |
| 通道复用 | 输出 `{x,y,netId}` 写入 design.stitching——固定孔标记/路由避让/DRC/Gerber 钻孔/IPC-356 全链既有，零新增管线（实测 42/42 进钻孔表） |
| CLI | `thermal <design> <compId> [--pitch --cols --rows --apply]`，--apply 回写 + 最小栅格同步（与 currents 同口径） |
| 校验 | 21a（warn→stitching 补齐→ok）、21b（42 孔 + DRC 0 + 钻孔表）、21c（舌孔滤除）、21d（检查表行） |
| 提交 | 70d3ed0 |

**21a 深检发现**：测试初稿给 2mm 圆焊盘布 6 孔阵列——正确行为是只放 1 孔
（可用半径 0.7mm，pitch 1.0 的邻点全越界）。场景错误而非实现错误，测试改用
4×4mm 盘并加 `added ≥6` 断言。

### 批次3：阻抗自动定档收口

| 项 | 内容 |
|---|---|
| 现状确认 | netMeta（L660）已按 nets[].diffZ 反查 sFor 建耦合走廊——计划所称"部分接线"实为基本完整；缺口在①显式 gap 字段（schema 注释已声明未消费）②报告面③单一事实源 |
| pairGapFor | 单一事实源：显式 `rules.pairs[].gap`（展开 nets[].pairGap）优先，否则 diffZ（缺省 90Ω）反查。**按 id 归位 design 网**——调用方可能传会话内部网对象 |
| 消费点统一 | netMeta 耦合走廊 / compactPairs 限带 A* / 压实报告 ratioBefore / DRC 差分耦合度——无显式 gap 时计算路径与旧代码逐值相同（位级兼容） |
| 校验语义 | gap < clearance 拦截（对内间隙边到边低于全局间距必 DRC 违规）；与线宽无关（0.3mm 线 0.15mm 缝物理合法——初版误用"gap≤线宽"口径，深检自纠） |
| 报告面 | fabChecklist 阻抗组逐对行（不可达 warn 指向 gap 逃生门）；spec 门布线前拦截（2 层 90Ω 最低 ~137Ω，建议升 4 层/放宽/显式 gap） |
| 校验 | 22a（4 层 0.3mm 90Ω→S=0.25，zdiffAt(S)=90 奇偶模自洽）、22b（显式覆写+拦截）、22c（2 层诚实不可达）、22d（端到端耦合走廊 DRC 干净） |
| 提交 | 0a067db |

**深检抓到的真集成 bug**：compactPairs 向 pairGapFor 传**会话内部网对象**
（只有 id/i，无 pair/diffZ 字段）→ `!net.pair` 全部误判 → 限带重建全
skip-unreachable → pair-compact 4 测试红（stash bisect 确认因果）。修复：
pairGapFor 按 id 归位到 design.nets 再读声明——两种调用口径单一事实源。
教训：把"读声明"的函数做成公共 API 时，必须考虑调用方持有的对象谱系
（design.nets 成员 / 会话网 / result 网）。

## 三、批次4（层位感知）：立项留档，不实施

按计划"架构决策项，如复杂则留档不实施"。留档如下：

**需求**：`nets[].preferredLayer`（如时钟网走内层、大电流走外层）→
ampWidthFor 自动切内外层铜厚口径 → 影响区按层位调整。

**为什么不是本轮做**：
1. "该网只走哪层"的约束如何进协商需要设计决策——passable 层过滤（硬约束，
   失败模式是新失败网）or 代价偏好（软约束，失败模式是约束不生效）——
   两者对协商收敛的影响完全不同，需探针实验数据支撑（同门图立项模式）。
2. ampWidthFor 的内层口径（0.5oz 反而需 1.6mm）与 maxTrackW 全板生效（L37）
   交互：内层声明可能反向放宽外层影响区——per-layer maxTrackW 是新的
   影响区维度，牵动 buildModel 位图结构。
3. 规模估算与门图（IntBox 房间代数）同阶——本轮三批的"查表+报告"模式
   不适用于"约束进协商"类改动。

**建议前置探针**（立项时）：取 M1 的 p05（512 焊盘 4 层）标 3 个网
preferredLayer=top，分别测 passable 过滤 vs 代价偏好的连通率/DRC/耗时
三口径，再决定立项形态。

### 探针结果（0.14.7 批次5 已做，关闭建议）

机制：`nets[].preferredLayer`（探针级，'top'/'bottom'/层号 → normalize 规范化 →
会话网 prefL → passable + astar 内联硬层位过滤，无声明网位级不变）。永久测试 26a。

p05（130 网/512 焊盘/4 层/grid 0.5）实测，3 个跨板长网（n3/n67/n99，55~58mm）
强制单层 top vs 基线：

| 口径 | 基线 | 强制单层 |
|---|---|---|
| 连通 | **512/512 complete** | **506/512 partial（−6）** |
| 探针三网 | 各 2/2（自然走 L0/1/2） | **全 0/2** |
| DRC error | 0 | **3** |
| 耗时 | 28.7s | 46.3s（+61%） |
| 过孔 | 228 | 314（+38%——其余网被迫重排） |

**结论：关闭**。硬层位约束在中等拥塞板上不可吸收——仅 3 个网（占 2.3%）就
引发连通/DRC/耗时三重劣化，顶层容量不足以承载跨板长网。代价偏好（软约束）
变体仍是唯一候选方向，但按门图教训（协商参数类改动三板 no-gain），立项前
需先证"软偏好能实际改变层位选择"的探针——若软偏好只是被拥塞完全淹没，
则整族不立项。声明字段保留（探针级，语义=硬约束，手册注明风险）。
