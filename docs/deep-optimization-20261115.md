# 深度优化：首次大网计算、候选网几何审计与会话生命周期

## 范围与原则

本轮接续 [上一轮复查](optimization-review-followup.md)，不重写已验证的路由策略，不增加运行时依赖。改动前将当时的引擎/UI 保存到本地 `.scratch/deep-review-20261115/`，用于完整管线前后对比。保留所有既有未提交改动；开始时已存在的用户工程结果修改不属于本轮优化。

## 1. 首次大网络长度下界：O(P³) → O(P²)

位置：[netLowerBound](../src/engine.mjs)。上一轮只避免面板重复求解，首次计算仍要执行 Prim：每加一个点，原实现重扫“未入树点 × 全部已入树点”，距离评估次数为 `(P³-P)/6`。

现在用 `Float64Array` 保存各未入树点到当前树的最近距离，只与刚加入的点进行松弛，距离评估恰为 `P(P-1)/2`，时间 O(P²)、额外空间 O(P)。

不去重、不更改小网精确 RMST 分支、不改变原始点数 >10 的切换阈值。原始索引升序扫描与严格 `<` 保留同距选点和浮点求和顺序；不是以精度或算法质量换速度。

### 独立实测

[基准脚本](../tests/bench-net-lower-bound.mjs)；Node v24.21.0 / Windows x64，5 次交错前后测量中位数，无 UI 缓存。JavaScript 函数先预热，但每次都重新计算整网，无跨调用结果缓存。

| 焊盘数 | 原实现 | 新实现 | 提速 |
|---:|---:|---:|---:|
| 100 | 2.367 ms | 0.491 ms | 4.82× |
| 300 | 98.348 ms | 1.354 ms | 72.61× |
| 600 | 340.182 ms | 3.414 ms | 99.63× |
| 1000 | 1649.463 ms | 9.669 ms | 170.59× |

以上是下界函数本身，不是整页或整板布线提速倍数。不同数据、JIT 和机器负载会影响耗时。

### 验证

[冻结的旧函数参考](../tests/net-lower-bound-reference.mjs) 只复制原函数，未复制整份引擎；[测试](../tests/net-lower-bound.test.mjs) 覆盖：

- 240 个固定种子的随机/重复坐标大网、小网随机与 9/10 点精确分支。
- 11 个原始焊盘但只有 3 个不同坐标时，仍按旧规则进入 MST，不误启用 RMST。
- 同距网格、同坐标、直线、符号零、极小/极大坐标、溢出及输入重排。
- 100/300/600/1000 点结果严格相等、调用者数据不变。
- 对真实函数计数，断言距离评估精确为 `P(P-1)/2`，不靠易抖动的计时断言证明复杂度。

## 2. 形状补线只评估候选网的走线段冲突

原 `netGeoVio` 每次用 `auditGeometry([candidate,...rest]) - auditGeometry(rest)` 计算候选网引入的段-段违规。绝大多数与候选网无关的全板段对被扫描两次，再在整数计数中抵消。

新增内部 `countNetSegmentViolations`，只比较候选网与其他网络/固定手动铜的段。设全板 S 段、候选 A 段，直接检查约 O(A×S)，避免两次全板排序与扫描。按层分组、bbox 快筛，保留全板扫描的参数方向、间距表达式、零长度阈值和同网豁免；焊盘、过孔等后续违规家族不改。

### 验证与收益边界

[差分测试](../tests/net-geometry-count.test.mjs) 包含手动铜、混合宽度、层跳转、零长度和精确间距边界；160 块固定种子板 × 6 候选网，与“两次全板审计之差”逐个整数相等。数字 ID 和字符串 ID、反向端点均覆盖。

[微基准](../tests/bench-candidate-geometry.mjs) 比较 16 次候选网段审计，5 次中位数：

| 数据 | 原两次整板审计 | 新候选审计 | 说明 |
|---|---:|---:|---|
| 密集合成板，60 网 / 720 段 | 587.78 ms | 45.09 ms | 约 13.04× |
| ext-fable-03 初始存档，24 个结果网络 / 216 段 | 6.40 ms | 6.19 ms | 约 1.03×，可视为中性 |

不将密集合成数据的收益推广为所有板型的收益。小型、稀疏或候选网占比很大的输入可能无明显收益。

## 3. 取消、失败与 Worker 会话保持一致

位置：[UI 路由状态](../src/ui.js)、[状态测试](../tests/ui-routing-state.test.mjs)。

此前 Stop/Escape 销毁 Worker，但 UI 的 `app.session` 不一定同步失效，尤其形状补线 catch 完成后仍可能为 true。下一次单网重布会新建一个没有模型的 Worker，再由后端报错。异步失败还可能留下已局部突变的 Worker 会话。

改为统一的 `invalidateRoutingSession()`：先清 UI 会话，再终止 Worker。Stop、Escape、quickStop 转发以及 route/reroute/shapePatch 失败路径走同一失效逻辑。

- 保持旧语义：完整布线开始/取消会清空当前自动结果。
- 单网重布或形状补线取消/失败则保留旧结果和设计，只废弃会话。
- 形状补线取消有明确“保留原布线结果”提示，不冒充成功。
- 单网重布入口还核对实际 Worker 是否存在，兜住空闲期 Worker 崩溃没有 UI await/catch 的场景。
- 控件 disabled 状态、进度条、迟到消息和取消后重新整体布线均受回归保护。

测试执行真实 UI 函数/事件处理器和真实 WorkerClient，只有 DOM、绘图与 Worker 传输是替身。先对旧源码验证失败，再修复；测试不仅检查报错文本，也检查是否创建了无会话 Worker、是否误删原结果。
