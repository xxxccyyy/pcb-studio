## 二、已验证教训（先实验验证再记录）

### L22 自检与 DRC 的距离口径差（"口径家族"第 5 例）→ 已修复

- **现象**（n90）：自检报告"网表完整"，DRC 报 4 处「焊盘间距 0.177mm < 0.2mm」——全部是 PLCC 四角相邻边焊盘。
- **根因**：自检用 **L∞ 矩形分离度**（max(dx-分离, dy-分离) = 0.125 ≥ 0 通过），DRC 用 **欧氏角距**（hypot = 0.177 < 0.2 判违）。同一对焊盘，两种"距离"口径结论相反。
- **修复**：① plcc44 角偏移 1.35 → 1.45（欧氏角距 0.177 → 0.318）；② 自检改用与 DRC 相同的 padGap 口径（重叠→负重叠量，双轴分离→欧氏角距）。
- **A/B**：n90 修复前 79/79 + 4 错 → 修复后 **79/79 + 0 错（91.7s）**。
- **泛化**：H1 罚金归零、L7 恰界容差、L13 同网孔距、L21 采样漏检、L22 口径差——五例同族：**任何几何判断必须逐处核对口径；自检工具与被查工具必须共用同一实现**（本轮 spec 门直接调用引擎 `padGap`，从根上消除两套实现）。

### L23 边缘定位连接器必须锚定（L16 的边界条件细化）→ 已验证

- **现象**（n89）：金手指 J1 被退火从板边推开 ~1.4mm（贴边罚 R5 L6 的预期行为），布线虽通过但**产品意图被破坏**——金手指位置由卡槽对位决定，不是布局偏好。
- **A/B**：不锚定 510s / via 58 / 位置漂移 → **锚定 J1：181s / via 32 / 位置精确保持**——快 2.8×、过孔近半。
- **与 L16 的关系**（不矛盾，是细化）：L16 说"spec 布局没有明确优势时不要锚"；L23 补充"**位置带产品级几何约束的元件（金手指/面板接口/安装对位）必须锚**——它的位置是规格输入，不是可优化变量"。操作规程：锚定决策看"这个位置是设计出来的还是退火能更好的"。
- 已回写 AI-使用手册 §3 决策规程。

### L24 正收益：12 种新封装/几何首测零引擎 bug

- 六轮加固（罚金下限/贴边罚/口袋罚/孔边距口径/美化精确距离）之后，第七轮 12 个全新封装与几何家族——细间距（TSSOP/MSOP/HSOP）、异形（J 引脚/圆周 THT/板边焊盘/双排宽总线）、功率（散热盘/升压拓扑/高压网）——**全部无需改引擎通过**。
- 唯一失败是 spec 级（L22 PLCC 角距），由 DRC 正确拦截。
- **结论**：前六轮的修复是"普适几何规则"而非"补丁堆叠"——引擎对焊盘几何的泛化能力得到一轮独立验证。

### L25 spec 自检门工具化（本轮深度优化）

- `ai/pcb.mjs spec` 在原有检查（栅格前提/坏引用/单脚网/线宽极限）基础上新增四类：**空网、同元件焊盘间距（DRC padGap 同口径）、出板（铜边）、THT 环宽（L15 三联动）**。
- **验证**：复刻旧 1.35 偏移的 PLCC spec → spec 阶段即拦截 `U1-1/U1-44 0.177mm < 0.2mm`（与 DRC 结论一致）；n73 干净 spec 零误报；255 项回归全过。
- **价值**：AI 手册工作流第一步就是 `spec`——这四类失败（R5 空网假绿、R7 角距、R6/R7 出板、R5 环宽）从此在布线前拦截，不再依赖下游 DRC 兜底。

## 三、spec 自检门战果（第三轮连续验证）

本轮生成器自检（内嵌版）累计拦截 **8 个项目 17 处 spec bug**：出板 ×10、单脚网 ×4、空网 ×3、坏引用 ×2——含**第六轮同款错误复发**（`netObjs` 漏 `nets:` 键，n90/n91）。门的价值不随熟练度消失：批量生成 spec 必过自检门，此规程三轮零例外。
