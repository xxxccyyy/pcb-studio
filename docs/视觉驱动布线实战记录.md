# 视觉驱动布线实战记录（Fable 三板：82-99/95-112 → 诚实口径 92/95、109/112、110/110）

> 2026-11-18 实战、2026-11-20 假绿审计后校准。三块真实外部工程（Fable USB-C 4 层板，
> 132-148 焊盘），自动布线分别卡在 82/95、95-98/112、99-110/110 的天花板；用「视觉驱动
> 布线」循环攻克剩余难点。**2026-11-20 审计推翻了本文早期版本的「100% 布通、DRC 0 err」
> 结论**——那是三重假绿叠加的产物（见 §7）。当前诚实终态：
>
> | 板 | 诚实连通 | DRC error | 未连明细 |
> |---|---|---|---|
> | fable-01 | **92/95** | 3 | n3 U2-15（围死）+ n9 ×2（围死）+ 1 条过孔间距 0.175mm（≥JLC 0.10） |
> | fable-02 | **109/112** | 1 | 3V3 ×3（MIC 侧围死类） |
> | fable-03 | **110/110 全通** | 1 | 无未连通；1 条 NC 盘邻接（U1-24 浮动铜，电学无害） |
>
> 未连通的 3+3 盘全部源于**外部设计数据的焊盘缺陷**（见 §7.4），属"给定该数据不可解"，
> 已在文档中逐盘留痕。本文记录方法论、踩过的坑与工具链改进。

## 0. 核心思想

自动布线卡壳时，「为什么没布通」的答案在**图上**：预拉线（冰青虚线）就是引擎告诉你的
"想走但走不了"的路径。AI 用视觉看图 → 人工级判断走廊 → 验证器核算间距 → 注入手工走线
→ 连通分量权威复核——把「AI 布线」升级成「AI 看着布线」。

## 1. 工具链（全部已有能力的组合）

| 步骤 | 工具 | 作用 |
|---|---|---|
| 看图 | `GET /api/render?highlight=X&crop=x,y,w,h` | 确定性几何渲染+高亮，多模态目检 |
| 定位 | `GET /api/query?net=X` | 焊盘精确坐标（**端点必须用它，别用组心**） |
| 判障 | `POST /api/why` | 逐开边 blockers——几何近似，最终以验证器为准 |
| 验证 | `POST /api/verify-path` | 候选折线逐点检查间距（层匹配+端点豁免），干净才注入 |
| 注入 | `POST /api/edit` / design.manual | 手工走线进入连通判定/DRC/导出全链 |
| 复核 | **连通分量重算**（refreshConn） | **连通权威**——最大分量焊盘数，假绿免疫（见 §7.2） |
| 收尾 | `pour` + 缝合孔 | GND 双层铺铜 + 热辐条背书口径（见 §7.3） |

## 2. 循环（每根网重复）

```
1. /api/why → 失败网清单（按 lb 排序，先攻贵的）
2. /api/query?net=X → 焊盘坐标
3. /api/render?highlight=X&crop=… → 目检，找空走廊
   （三个黄金走廊来源：板边条带、空闲内层、大封装之间的缝隙）
4. 规划折线（正交优先，见 §4 坑位清单）
5. verify-path 验证 → 有违规就调航点（绕障、换层、换走廊）
6. 注入 → refreshConn 复核该网分量数
7. 全网清零 → 下一网；全部清零 → GND 铺铜收尾
```

## 3. 实战成果明细（2026-11-20 校准后）

### fable-01（45×35，132p/17n，grid 0.7，交付版 82/95 幻影）
- 诚实基线：**纯路由 27/95**（交付版的 82-86 里有 55 个"无铜幻影"，见 §7.1）
- route + shape-patch 双轮 + 严格协商：**86→88/95**
- GND 底/顶双层 pour（1507/1041mm²）+ 41 缝合孔 + 热辐条背书：**92/95**
- 视觉布线攻 n3（3V3 顶层 pour 接入）、U2-15 桥（L3 底层绕行）
- **终态 92/95**；U2-15 与 n9 两端因焊盘数据缺陷围死（§7.4）
- 数据修复 5 处：J1-A7/B5/B1A12 重排（USB_DP/DM 共点分离）、U2-3/U2-4 槽位互换

### fable-02（60×35，148p/19n，grid 0.5，交付版 95/112 幻影）
- 旧版 12 条手工桥与修复后焊盘全面冲突（旧时代几何）→ 全部剥离
- 诚实基线：纯路由 61/112 → shape-patch 63/112 → GND 双层 pour 背书 **109/112**
- 3V3 顶层 pour 尝试：56.8mm²，6 盘辐条不可达（孤岛自动移除）——按 pour 自己的
  unconnectedPads 背书口径如实计 109/112
- 数据修复 1 处：U2-9（n20）脱离 U2-10（GND）共点

### fable-03（55×40，148p/24n，grid 0.5，交付版 99/110）
- **route + shape-patch + GND 双层 pour 一次到位 110/110 全通**
- 数据修复 0 处（三板中唯一无焊盘缺陷的）
- DRC 1 err：U1-24（NC 盘，netId null）与 n9 走线 -0.095 重叠——浮动铜、电学无害，
  JLC 可制造（NC 盘邻接类，与真实 EDA 的 NC 处理一致）

## 4. 坑位清单（每条都是真踩过才写的）

1. **manual 段端点必须精确焊盘坐标**（`/api/query` 的 toFixed(3)），舍入到 0.1 会跨格
   导致 ratsnest 不认（C2-1@33.725 vs 33.7 的 0.025mm 之差翻过车）
2. **内层斜线会被 ratsnest 格角跳变吞掉**：45° 斜线沿格角穿越时 4 邻域并查断链——
   内层段一律改正交 L 型，或相信走廊标记半径 0.71 格的补偿
3. **manual 段累加注入**：按段去重累加，别「同网先清后注」
4. **层号要显式保留**：注入脚本硬编码 `l:0` 会让内层路径全废——`l: p.l ?? 0`
5. **验证器的层匹配**：顶层段只撞 top/both 焊盘，内层段只撞 bottom/both
6. **端点豁免**：起终点 1.5mm 内的异网近邻焊盘是逃逸的物理现实，豁免圈必须开
7. **connected 静态快照会过期**：summary/drc-live 一律实时连通分量重算（§7.2），
   绝不回退到文件里的旧 stats
8. **GND 类网用铺铜不用走线**：40+ 脚电源地网的正确归宿；热辐条接入按 pour 的
   unconnectedPads 背书（0.15.2 起 checkDRC 同口径）
9. **`pour` 的 result 写回 args[1]**（输入 result 文件原地更新），不是 --result 路径
10. **PCB 上没有绝对空旷，只有还没看的层**：顶层堵了看内层，内层堵了看底层
    （fable-01 的 n3 桥就是 L0 短引出 + L3 底层 4mm 绕行 + 同网盘内过孔收尾）
11. **trim 铜皮段之前先确认每盘的替代通路**（fable-02 翻过车：一次 trim 断了 9 盘）——
    每次只 trim 一条精确匹配的折线，trim 后立刻 recount
12. **同网过孔入盘是合法的**（GND 盘里打 GND 缝合孔直通底层 pour）——围死盘的
    标准逃生术；异网过孔入盘则是短路级错误

## 5. 工具链改进（已固化进项目）

- **refreshConn 连通分量化**（exe/board-info.mjs）：「逐点落走廊 + max 不倒退」的
  假绿口径全部废除——现在按铜格连通分量取最大组（与引擎 computeRatsnest 同口径），
  外加铜皮逐格心判定、缝合孔、热辐条背书（pour.unconnectedPads 并查合并语义）
- **boardSummary 实时重算**：/api/summary 不再回读文件里的过期 stats
- **checkDRC 未连通的铺铜背书**：pour 点名孤立的才报，辐条接入的不再误报
- **recountConnected**（引擎新导出）：shape-patch/并行装配等所有结果生产者落盘前的
  统一兜底——connected 必须由铜格分量决定
- **buildResult 装配点诚实口径**：会话内计数引用已拆除铜皮的网绝不虚报
- **verify-path / render crop+highlight**：视觉布线的安全网与眼睛

## 6. 一句话总结

**自动布线的天花板不是算法极限，是「没有视觉的搜索」+「不诚实的计账」。** 截屏看一眼
省十分钟盲试；连通分量是唯一的裁判；手工段的每个端点都要落在焊盘中心的格子里；
报出来的每一个数字都要经得起「铜皮真的在吗」的追问。

## 7. 假绿审计（2026-11-20，本文早期版本结论被推翻的完整复盘）

### 7.1 三重假绿源

1. **过期几何**：result 在 0.65 栅格时代布线，design 后来被 normalize 到 0.7——
   路径与焊盘系统性错位 0.13-0.18mm，原本的近距全部变成重叠。20 条间距 err 全是
   这个伪影；修法只有重跑口径（placed 设计 + 引擎自报 minimumRoutingGrid 全新布线）。
2. **shape-patch 不序列化**：补线协商的 connected 计账含"借道但未落盘"的铜——
   f1 实测 n3 10/11、n4 38/40、n6 4/5 声称连通而 paths/cells 全空，Gerber/导出全断。
   修法：落盘前 recountConnected（引擎新导出，铜格分量重算）。
3. **装配计数虚高**：ripNet 拆网清铜不清 connected——被拆待重布的网以空壳进入
   buildResult。修法：buildResult 装配点按铜格分量重算（轨迹位级不变）。

### 7.2 「逐点落走廊」的假绿机制

旧 refreshConn 只判"焊盘是否落在某段走廊上"，不判各段彼此是否连通——n5/n6/n18
三网各断成 2 分量仍报 95/95。现替换为连通分量判定（4 邻域 + 过孔跨层 + 同焊盘
覆盖单元互连，与 computeRatsnest 同口径），connected = 最大分量焊盘数，
另记 groups/split 供断链定位。连带修复：`var` 提升导致背书集合跨网残留
（fable-02 实测 574/95 的重复计数）。

### 7.3 铺铜辐条背书

GND 类网的连接方式就是铺铜：热辐条接触是真实 EDA 认可的接入方式，但格心采样
会漏掉细辐条。现按 pour 自己的几何判定（unconnectedPads）背书：背书盘以
**并查合并**（只增不减）并入铜皮主分量；pour 点名孤立的才报未连通。
fable-01 实测教训：背书合并若用"拽出重排"语义会把背书盘从既有走线组里拆走
（109→106 的假倒退），必须用 UNION。

### 7.4 设计数据缺陷清单（外部工程导入问题，未擅自改网表）

- **fable-01 J1（USB-C）**：A6/A7（USB_DP/DM）、B4A9/B5（VBUS/CC2）不同网焊盘
  **完全共点**；A5/B7 同网共点。修复：A7 → 同网邻位 22.05、B5 → 25.60、
  B1A12 让位 26.30（全板跨 comp 验证最近异网距 ≥0.25）
- **fable-01 U2（QFN-17）**：原始数据 U2-3/4、9/10、11/12 共点；placement 又把
  U2-2/U2-3 压到同点。修复：U2-3 → 26.30 槽位、U2-4 → (27.05,14.70)
- **边缘焊盘宽高翻转**（疑似根因）：U2-1..16 全部 0.25×0.6 竖条——QFN 边缘焊盘
  应沿边横向（0.6×0.25），现值导致 0.5 间距上 0.6 长度互相重叠 0.1、逃生道缺失。
  未擅自翻转（会级联 R4-2/U2-2/n7 三面包夹的再布局），**作为 U2-15/n9 围死的
  根因记录**。U1 的 0.9×1.5 长盘同理（SOP 长盘特征，DRC 不查盘-盘，保留）
- **NC 盘未赋网**：U1-19/20/24/26/27/28/31/32/37/38/41d/41h 等 netId=null——
  DRC 按异网处理一切邻近铜皮，产生一批"NC 盘邻近"类间距报错（非布线错误）
- **fable-02 U2-9/10 共点**（n20/GND）：修复 U2-9 → (50.75,3.25)
