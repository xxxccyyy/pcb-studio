# 深度优化报告——0.14.11 checkDRC 桶格（2026-11-16d）

> 定位：0.14.10 转正后按剖析重定方向。新默认（组合一致场）下热点结构大变——搜索
> 瘦身后 checkDRC 被放大为第二热点，本轮以保序桶格根除其主 cost。

## 1. 剖析（icebreaker@12，50.3s）

| 热点 | 占比 | 说明 |
|---|---:|---|
| astar | 36% | 组合场下展开减半（4600→~2000/次） |
| fillDistanceMap | 24% | 17k 次 × 0.7ms（组合 BFS + 缓存后掩码） |
| **checkDRC** | **17%** | **仅 70 次调用但单次 144ms——全部来自 jointReroute 逐 mask 计分** |
| rmstTasks | 8% | 全对 O(V²) Dijkstra（堆化非位级不变，留档不动的第三轮） |
| score(jointReroute) | 4% | buildResult 0.7ms 可忽略 |

## 2. checkDRC 家族计时（注入计时点对）

| 家族 | 占比 | 静态性 |
|---|---:|---|
| **pad-pad（O(P²) 双循环）** | **82%** | 纯静态（焊盘 design 内不变） |
| seg-pad/禁布/出板 | 13% | 动态（走线） |
| 插件孔+孔边距 | 2% | 混合 |
| 过孔族 | 2% | 动态 |
| 其余 | ~1% | |

段间距扫描（经典排序扫）只占 0——真正的重炮是 pad-pad 的 O(P²) 裸扫
（冰拳板 189k 对、bbox 过滤后仍 ~86k 对 × 层检查 × padGap）。

## 3. 改动：保序桶格（pad-pad + seg-pad）

- **pad-pad**：桶边长 = _padR2（bbox 过滤界）→ 存活对必落相邻桶；逐 i 收集邻桶
  候选（j>i）按 j 升序求值 → 求值序 = 原 (i,j) 双循环序 → **findings 数组逐位一致**。
  跳过的对必不过 bbox 过滤（保守超集，不可能违规）。
- **seg-pad**：按层桶化（padOnLayer 展开到层号），桶边长 = 最大 _sR 上界
  （maxTrackW/2+_clrMax+_segMaxPadR），每段 bbox+margin 覆盖桶收集候选、按 pad
  索引升序求值、首违即 break——与原全量序语义一致。
- **每次调用重建桶**（O(P)≈微秒级）：design.pads 可能被 autoPlace 原地改写，
  跨调用缓存有失效风险，重建成本可忽略——零失效风险换微小成本。
- 收益面：**所有 checkDRC 消费方**（GUI DRC 面板、CLI `drc`、deliver 门禁、
  jointReroute 计分）——大板单次 144ms → ~20ms 级。

## 4. 验证

- **findings 数组逐字节差分**：180 板×配置 × 多协商采样态（step 中间态/终态/
  optimize 后），冻结 0.14.10 vs 当前，**0 处不一致**（403k 字节 findings 比对）。
- 真实板 A/B：icebreaker@12 **47.9→43.0s（10.3%）**、fable-03 0.9%、h2 1.6%
  （焊盘密度决定收益），**结果 SHA-256 全部一致**。
- 全量 npm test exit 0（80 核心 + 285 node:test + 48 书籍 + 17 CLI + 39 模糊 +
  7 深检 + 48 优化锁）+ 浏览器四组 60 项全过；search-regression 金标准不变通过
  （输出逐位一致 → 无需重录）。

## 5. 边界与后续

- 收益与焊盘密度成正比：BGA/FPGA 类密脚板收益最大，稀疏板接近持平。
- rmstTasks O(V²) Dijkstra 堆化（8%）：改 prev 平手序 → 分解不同 → 非位级不变，
  若做需质量车道 A/B + 金标准重录，本轮不做。
- jointReroute 局部化计分：pad-pad 桶格后静态家族已便宜，剩余动态家族 ~17ms/次
  ×70 次 ≈ 1.2s，逐家族等价证明的复杂度收益比转差——留档降级。
- astar(36%)+fillDistanceMap(24%) 的剩余空间：微调量级（~3%），本轮评估后不取
  （代码分裂风险 > 收益）。
