## 1. P0 回归修复：CRLF 行尾（提交前必读）

**现象**：0.14.4 提交 6a6896d 专门做过 LF 归一化（提交信息原话"外部 AI 测试的源码标记定位
全部依赖 LF"），但紧接着的 6d11acb 又把 `src/engine.mjs` 整文件写成 CRLF 提交——7 个源码
锚点测试（via-ring-cache / congestion-neighborhood / fixed-via-drill / net-lower-bound 等，
用 `readFileSync`+`indexOf('…\n…')` 定位引擎源码块）在真实工作区全灭，`via-ring-cache`
4 测试挂 1。`npm run check` 拦不住它：build.mjs 读源码时就地归一化 CRLF，把问题**掩盖**
而非暴露。

**修复三件套**：
1. `src/engine.mjs`、`src/index.template.html` 归一化回 LF（9577+306 行）；
2. 新增 `.gitattributes`：`* text=auto eol=lf`（png/jpg/ico binary）——仓库层锁死，
   外部 python 补丁工具再写 CRLF 也会在 add/commit 时归一；
3. `scripts/build.mjs --check` 新增**行尾守门**：5 个注入源任一含 CR 即报错并给出归一化
   命令。验证方式：临时把 engine.mjs 注回 CRLF → 守门如实报错 → 恢复 LF → 全绿。
   CI 同款复核（见 §2）。

**教训**：行尾转换脚本绝不能用 `open('wb').write(open('rb').read()…)` 同路径一行式——
`wb` 先截断，右侧读到的是空文件（本轮实测把 engine.mjs 清成 0 字节，git checkout 恢复）。
正确姿势：先读入变量，再写回。此外由于外部轮并发写入（§5），engine.mjs 在本轮期间
多次被外部工具重新写成 CRLF——守门每次都如实抓到，`.gitattributes` 在提交时兜底归一。

## 4. 深优基建：对拍架转正（留档缺口修复）

CHANGELOG 0.14.4 记录过"留痕缺口"：各深优轮的 diff 对拍架留在 `.scratch/` 未随库存档，
复现链断裂。本轮把对拍架转正为常备工具 `scripts/ab-diff.mjs`：

- `node scripts/ab-diff.mjs [--before <git-ref>] [--quick]`——before 侧从任意 git 引用
  重建引擎（归一化 LF 写 `.scratch/engine-before.mjs` 独立模块实例），after 侧=工作区，
  同进程双实例跑 11 案例 sha256 对拍（`--quick` 跳过 fable-03 三条 >30s 慢案例）。
- 11 案例口径对齐 20261114 深优轮：3 内置示例 routeBoard、m1-p01 量产板、fable-03
  栅格全链/形状补线/shape-only/铺铜/DRC 全口径、e555 autoPlace、emcu placeAndRoute、
  压力板 optimize(3)。
- **确定性口径修正（重要发现）**：routeBoard 返回 `{result, session}`——`session.t0`
  是 Date.now() 墙钟，typed arrays 非交付物；clean() 需整枝剔除 session + timeMs 后哈希。
  实测 **routeBoard 的 `result` 字段跨进程/跨运行逐字节确定**（0.14.4 引擎 e555 三连跑
  同哈希）——位级对拍成立前提的再确认；未来某轮若破坏确定性，本工具直接暴露。
- 现状基线（工作区=外部轮进行中状态，before=HEAD）：7/7 快案例全 PASS。
